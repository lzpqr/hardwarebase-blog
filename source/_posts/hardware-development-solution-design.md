方案设计是硬件项目成败的关键节点，也是把技术真正转化为产品的重要环节。

需求分析回答“要做什么”，方案设计则要回答“怎么做，为什么这么做，以及这样做是否可行”。在正式进入原理图和 PCB 之前，需要先把系统架构、关键指标、器件路线、结构约束和验证方法想清楚。

方案设计的价值，是用相对较小的试错成本，换取后续设计更高的确定性。

> 本文是硬件开发流程系列的第三篇。建议先阅读 [硬件设计开发流程：需求分析篇](/posts/hardware-development-requirements-analysis/)，整体流程可以参考 [硬件设计开发流程：从需求分析到量产导入](/posts/hardware-development-process/)。

## 方案设计文档的整体结构

| 章节 | 主要内容 |
| --- | --- |
| 概述 | 项目背景、目标、原则和范围 |
| 功能性能指标 | 将需求转化为可以检查的技术指标 |
| 关键指标分析 | 说明关键指标的实现途径 |
| 总体方案 | 系统框图、模块划分和接口定义 |
| 关键器件选型 | 型号、规格、供应、价格和替代方案 |
| PCB 约束 | 尺寸、叠层、布局、散热、屏蔽和滤波 |
| 结构设计 | 结构要求、工艺要求和装配方式 |
| 测试与验证 | 测试目的、项目、条件和判定标准 |
| 风险评估 | 技术、物料、成本和周期风险 |
| 六性设计 | 环境、可靠、维修、测试和保障性设计 |
| 周期与人员 | 项目进度、任务分解和人员分工 |
| 交付与配置 | 成果形式、文档和交付清单 |

## 1. 概述

概述章节用于建立项目共识，主要描述：

- 项目背景；
- 设计原则；
- 研制目标；
- 项目支撑；
- 国内外发展情况；
- 术语和缩写定义。

概述不需要堆砌细节，但要让评审人员快速理解项目为什么做、准备做到什么程度，以及方案设计遵循哪些基本原则。

## 2. 功能性能指标

方案设计要依据需求规格说明书，重新梳理功能需求和指标要求。

建议使用指标对照表，把需求、方案和响应位置对应起来：

| 指标项目 | 技术指标要求 | 本方案达到的指标 | 偏离情况 | 文件索引 |
| --- | --- | --- | --- | --- |
| 指标一 | 【填写要求】 | 【填写方案值】 | 【满足/偏离】 | 【页码或章节】 |
| 指标二 | 【填写要求】 | 【填写方案值】 | 【满足/偏离】 | 【页码或章节】 |

如果某项指标是必须满足项，可以标记为：

```text
★ 必须满足
```

方案不能只写“能够满足”，还要说明通过什么设计、器件或结构实现，以及最终如何验证。

## 3. 关键指标分析及实现途径

针对关键指标，建议分为两部分描述：

1. 指标要求是什么；
2. 计划通过什么途径实现。

例如，通信距离、接口速率、功耗、温升和可靠性指标，都不能只给出目标值，还要说明设计余量、实现方法和验证条件。

关键指标应优先覆盖：

- 直接影响功能是否成立的指标；
- 技术难度较高的指标；
- 成本或周期影响较大的指标；
- 客户明确要求且不可妥协的指标。

## 4. 总体方案设计

总体方案可以分为硬件总体方案和软件总体方案。

主要内容包括：

- 整体系统框图及说明；
- 模块划分；
- 模块之间的关系；
- 关键接口定义；
- 供电和时钟分配；
- 软硬件职责边界；
- 数据流和控制流。

总体框图不应只是器件连线的罗列，还要体现系统如何工作、各模块如何协同，以及关键信号如何流动。

## 5. 关键器件选型

关键器件选型需要形成选型表，至少包含：

- 型号；
- 厂家；
- 规格参数；
- 参考价格；
- 替代型号；
- 产地；
- 供货周期；
- 生命周期状态。

选型时不能只看性能参数，还要综合考虑：

- 是否满足功能和环境要求；
- 封装和尺寸是否适合当前结构；
- 是否有稳定供货来源；
- 是否存在停产风险；
- 是否有兼容替代方案；
- 是否满足国产化要求；
- 软件和生态是否成熟；
- 总体成本是否可接受。

关键器件一旦确定，后续原理图、PCB、软件和采购都会受到影响，因此应在方案阶段完成充分比较和评审。

## 6. PCB 设计约束与布局规划

方案阶段不需要完成全部 PCB 设计，但需要提前明确约束条件。

### 尺寸和叠层

预估板卡尺寸，确认安装空间，并初步分配 PCB 叠层。

叠层会影响阻抗控制、信号完整性、电源完整性和制造成本，不能等到布线阶段才决定。

### 布局分区

根据电路功能进行分区，例如：

- 数字区；
- 模拟区；
- 射频区；
- 电源区；
- 接口区。

同时需要标明对外接口位置、螺丝孔位置、安装方向和其他结构约束。

### 散热设计

提前考虑散热方式，例如自然散热、金属壳体导热、风扇散热或导热材料。

PCB 上需要预留相应的露铜散热区域、风扇供电和控制接口。

### 屏蔽与滤波

方案阶段要明确：

- 需要屏蔽的区域；
- PCB 屏蔽开窗位置；
- 时钟线是否需要包地；
- 滤波电路放置位置；
- 接口防护和接地方式。

这些问题如果留到 PCB 后期处理，往往会导致布局大幅调整。

## 7. 结构设计

结构设计需要依据结构设计要求和工艺设计要求，说明：

- 结构设计思路；
- 外观方案；
- 内部空间分配；
- 安装和固定方式；
- 接口和按键位置；
- 散热路径；
- 天线净空；
- 装配工艺和可维修性。

硬件、结构和软件需要在方案阶段确认接口位置和空间边界。

## 8. 测试与验证

方案设计应同步考虑后续如何测试和验证。

测试与验证章节通常包括：

- 试验性质；
- 试验目的；
- 试验周期和地点；
- 被试装备和保障装备数量；
- 技术指标；
- 测试项目；
- 试验暂停、中断、恢复和终止条件；
- 测试记录和判定标准。

测试方案应在设计开始前提出，而不是样机完成后临时补充。

## 9. 风险评估

风险章节需要提出风险点和对应措施。

常见风险包括：

- 技术风险：关键指标无法实现；
- 物料风险：器件缺货、停产或价格波动；
- 成本风险：目标成本无法达到；
- 周期风险：研制、采购或认证时间不足；
- 软件和结构协同风险；
- 生产工艺和装配风险。

每一项风险应说明发生概率、影响程度、应对措施和责任人。

## 10. 六性设计

硬件方案需要关注六性设计，包括：

- 环境适应性；
- 可靠性；
- 维修性设计；
- 测试性设计；
- 保障性设计。

必要时还可以补充：

- 电磁兼容性；
- 三化设计；
- 安全设计；
- 可制造性设计。

六性不是后期附加工作，而是需要在方案阶段就纳入架构和器件选择。

## 11. 实施周期与人员安排

方案设计需要给出项目实施周期、进度安排、任务分解和人员分工。

进度安排应明确：

- 方案设计时间；
- 原理图和 PCB 时间；
- 制板和贴片时间；
- 调试和验证时间；
- 结构、软件和认证配合时间；
- 关键评审节点。

人员安排需要明确负责人、配合人员和交付节点，避免任务无人负责或多人重复工作。

## 12. 项目交付清单及配置

交付章节需要明确：

- 交付成果形式；
- 文档内容；
- 交付清单；
- 交付时间和地点；
- 配置管理方式。

根据需要，还可以补充：

- 团队研究基础；
- 质量保障措施；
- 沟通计划；
- 配置管理计划；
- 技术状态管理方式。

## 结语

方案设计不是简单画一张系统框图，而是把需求、技术路线、器件选择、结构约束、测试方法和项目计划放在一起进行系统判断。

先想清楚做什么、怎么做、为什么这么做，再输出文档并组织评审，才能让后续原理图、PCB、调试和量产建立在稳定的基础上。

> 方案阶段真正节省的时间，来自对错误路线的提前排除。
