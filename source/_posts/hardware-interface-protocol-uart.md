## 一、文档目的与适用范围

本文档规定硬件产品中 UART（Universal Asynchronous Receiver/Transmitter）接口的电气设计、电平标准选择、帧格式与波特率误差预算、拓扑与流控方式、PCB 布局、可靠性设计及测试验证要求，作为原理图设计、PCB 设计、器件选型与整机联调的通用依据。

适用范围：板内 TTL/CMOS 电平的 UART 互连（调试串口、主控与模组之间的命令通道），以及经电平转换后对外引出的 RS-232、RS-422/RS-485 接口。更高层的总线协议（如 Modbus RTU）不在本文档的电气规范范围内，但其物理层设计须满足本文要求。

## 二、接口概述

UART 是历史最悠久的异步串行通信方式之一，也是目前硬件产品中使用面最广的调试与命令通道，核心特征如下：

- **异步**：没有时钟线，收发双方各用各自的本地时钟，依靠事先约定的波特率保持节拍一致。
- **起止式帧同步**：每个字节以起始位开头、停止位结尾，接收端靠起始位的下降沿在每个帧边界重新同步，因此时钟误差不会跨帧累积。
- **最少三线**：TX（发送）、RX（接收）加一根共地 GND，构成全双工点对点链路；连接时本端 TX 接对端 RX。
- **电平多样**：UART 本身只是逻辑协议，与电气标准无关。实际物理层可以是 MCU 的 TTL/CMOS 电平，也可以是 RS-232 单端电平或 RS-422/RS-485 差分电平。
- **无寻址、无仲裁、无应答**：UART 只负责搬运字节，不具备总线管理与应用层可靠性能力，这些必须由上层协议补齐。
- **波特率范围宽**：常用 9600、19200、38400、57600、115200、230400、460800、921600，高性能 MCU 可达数 Mbps。

UART 的优势是引脚极省（两线全双工）、几乎所有 MCU 都原生支持、经电平转换后可实现远距离通信；代价是速率受时钟精度限制、原生拓扑不支持多机组网，且应用层必须自行补齐成帧与校验机制。

## 三、物理层设计

物理层要解决的问题是"用什么样的电气形式把这串异步比特传过去"，内容涵盖信号定义与连接、电平标准选择、波特率误差能否收敛、总线拓扑与流控方式，以及跨电平域的转换处理。

### （一）信号定义与连接

| 信号 | 方向 | 说明 |
| --- | --- | --- |
| TX | 输出 | 数据发送，空闲态保持高电平 |
| RX | 输入 | 数据接收，空闲态保持高电平 |
| GND | — | 必需共地，异步串行没有地无法建立电平参考 |
| RTS | 输出 | 请求发送，硬件流控输出，低有效 |
| CTS | 输入 | 清除发送，硬件流控输入，低有效 |

必须注意：TX 与 RX 的输入输出定义是相对各自设备而言的，因此两个设备互联时必须交叉连接——本端 TX 接对端 RX，本端 RX 接对端 TX。使用硬件流控时同样交叉：本端 RTS 接对端 CTS。这是 UART 应用中最常见的接线错误。

### （二）电平标准与适用距离

UART 逻辑信号必须依托具体的电气标准才能可靠传输，四种常用标准的对比如下：

| 电平标准 | 信号形式 | 逻辑电平 | 拓扑 | 典型距离 | 典型应用 |
| --- | --- | --- | --- | --- | --- |
| TTL/CMOS UART | 单端非平衡 | 0~VDD（1.8/3.3/5V） | 点对点全双工 | 板内，一般小于 0.5m | 调试串口、模组 AT 命令 |
| RS-232 | 单端非平衡，负逻辑 | 逻辑 1: -3~-15V；逻辑 0: +3~+15V | 点对点全双工 | ≤15m | PC 串口、工控仪表、老式设备 |
| RS-422 | 差分平衡 | 差分 ±2V 以上 | 1 发 10 收，四线全双工 | ≤1200m | 远距离点对点、广播分发 |
| RS-485 | 差分平衡 | 差分 ±1.5V 以上 | 半双工两线多点，32 单位负载（1/8 负载可到 256 节点） | ≤1200m | 工业现场总线、Modbus |

选择原则：板内短距离一律用 TTL 直连、无需收发器；需要抗干扰、远距离或多节点时，再在 MCU 的 TTL UART 外面增加 RS-232 或 RS-485 收发器芯片。

### （三）波特率与误差预算

异步通信没有时钟线，收发双方的波特率各自从其本地时钟分频得到，二者必然存在偏差。由于接收端在每个字节的起始位都会重新同步，误差只在一个帧内累积，因此只要保证帧内的最后一位仍能被正确采样即可。

工程上通用的要求是：收发双方波特率总偏差一般不超过 ±2%，建议按 ±1.5% 设计留裕量。偏差容限还与帧长度有关——数据位与校验位越多、采样点越靠近位边沿，容错空间越小。

以常见的 16 倍过采样 UART 为例，波特率分频系数与实际误差按下式计算：

```text
BRR = Fclk / ( 16 × BaudRate )
误差 = ( Fclk / ( 16 × BRR ) − Baud ) / Baud × 100%
```

由于分频系数只能取整数，实际波特率会与标称值产生舍入偏差，这正是时钟源选择的关键所在。传统做法优先选用能被常用波特率整除的晶振，如 11.0592MHz、22.1184MHz、7.3728MHz，可使常用波特率几乎零误差；现代 MCU 多内置小数波特率发生器或分数分频器，配合 PLL 可将误差压到 0.1% 以下。

使用内部 RC 振荡器的场合需要特别小心：RC 精度通常仅 ±1%~±5%，且随温度与电压漂移，高波特率下极易出现偶发帧错误。速率超过 115200bps 时应使用外部晶振。

### （四）拓扑形式

- **点对点**：UART 的标准形式，两个设备的 TX/RX 交叉相连，这是唯一被 UART 原生支持的拓扑。
- **禁止 TTL 电平并联**：多个 TTL 输出直接并接在同一根线上会互相驱动冲突，可能造成总线电平错误甚至损坏 GPIO。
- **多机组网方案**：需要多机通信时应改用 RS-485 总线（配合上层主从轮询协议），或使用串口多路复用、交换芯片做分时复用。
- **广播监听**：RS-422/RS-485 支持一发多收，可用于广播式数据分发，如 GNSS 授时报文的分发。

### （五）流控方式

| 方式 | 说明 | 适用场景 |
| --- | --- | --- |
| 无流控 | 仅 TX/RX/GND 三线，完全靠上层软件保证不丢数据 | 速率不高、缓冲充足、上行数据量小的简单场景 |
| 硬件流控 RTS/CTS | 接收方在缓冲区将满时通过 RTS 通知对方暂停发送 | 高速率、大数据量、接收方处理能力不足时必须使用 |
| 软件流控 XON/XOFF | 通过发送 0x11/0x13 控制字符暂停或恢复 | 不推荐用于二进制数据流，会与有效数据冲突 |

设计阶段即使暂时不需要流控，也建议把 RTS/CTS 引到 0Ω 电阻或测试点，为后续提速预留改造空间。

### （六）电平转换设计

MCU 侧的 UART 引脚输出的是 TTL/CMOS 电平，绝对不能直接与 RS-232 接口相连——RS-232 的 ±15V 电平会直接击穿 MCU 的 IO。

- **转 RS-232**：使用 MAX3232 类的电荷泵转换芯片，注意其外部电荷泵电容（典型 0.1μF）必须按手册就近放置；三线接法只需 TX、RX、GND。
- **转 RS-485/422**：半双工使用 MAX3485 类收发器，由 MCU 的一个 GPIO 控制 DE（驱动使能）与 RE（接收使能）；全双工 RS-422 需四线。
- **不同 TTL 电平域互连**（如 1.8V 与 3.3V 器件）：使用电平转换器件，TX 与 RX 方向相反，需按各自方向分别处理。

## 四、协议层设计

UART 的逻辑协议本身很简单，正因为如此，真正容易出问题的反而是那些"手册不会写、但双方必须约定一致"的参数，以及必须由应用层补齐的成帧规则。

### （一）帧格式

UART 的每一帧由四个字段依次构成：

| 字段 | 位数 | 说明 |
| --- | --- | --- |
| 起始位 | 1 位 | 低电平，标志一帧开始 |
| 数据位 | 5/6/7/8/9 位 | 通常为 8 位，低位先行（LSB first） |
| 校验位 | 0 或 1 位 | 无校验、奇校验、偶校验、Mark、Space |
| 停止位 | 1 / 1.5 / 2 位 | 高电平，标志一帧结束并留出线路恢复时间 |

线路空闲时 TX 保持高电平。最常用的配置是 115200-8-N-1（115200bps、8 位数据、无校验、1 位停止位），此时每帧共 10 位，位时间约 8.68μs，单帧约 86.8μs，理论字节吞吐约 11.5KB/s。

### （二）采样与同步机制

接收端持续监测 RX 线上的下降沿。检测到下降沿后，先等待半个位时间以确认这确实是起始位而非毛刺，随后在位时间的中心位置逐位采样。工程上普遍采用 16 倍过采样（部分 MCU 用 8 倍或更高倍率），并在采样窗口内多次取样取多数值，以此提高抗噪能力。

由于每帧都重新同步，波特率偏差只在一帧内累积，这正是前面要求总偏差控制在 ±2% 以内的原因。

### （三）错误检测

UART 硬件提供了基本错误标志，软件必须打开并使能它们，否则偶发的物理层问题会被系统性地忽略：

| 错误类型 | 触发条件 | 处理建议 |
| --- | --- | --- |
| 帧错误 Framing Error | 停止位采样到低电平 | 多为波特率偏差或帧格式不匹配，应复位接收状态机 |
| 奇偶错误 Parity Error | 校验位与数据位计算结果不符 | 累计计数并请求上层重传，UART 本身无重传能力 |
| 溢出错误 Overrun | 上一字节未被及时读走，新字节已到达 | 改用 DMA 接收，或提高中断优先级、加大缓冲深度 |
| Break 中断 | RX 持续低电平超过一帧时间 | 可作为链路断开或从机复位信号的上报途径 |

### （四）应用层成帧约定

UART 只搬运字节，既没有帧边界也没有地址概念；数据流到达时可能一次是一整包，也可能被拆成多次。因此应用层必须自行定义成帧规则，工程上常见两种做法：

- **特征值定帧**：帧头 + 长度 + 载荷 + CRC16/CRC8 校验 + 帧尾（如以 0xAA、0x55 开头）。可靠性最高，但需处理数据中恰好出现帧头的转义问题。
- **时间间隔定帧**：以总线上超过若干个字符时间的空闲作为一帧结束标志（Modbus RTU 采用 3.5 个字符时间）。实现简单，但对中断延迟敏感。

无论采用哪种方式，都应包含长度字段与 CRC 校验，并明确"帧头出现在数据中间"时的转义或超时丢弃策略。

### （五）波特率自适应

部分模组（如某些 GNSS、蓝牙透传模块）支持自动波特率：主机先发送约定字符（如 0x55 或 AT 命令），从机通过测量起始位宽度反推波特率。设计调试口时可利用此特性提升兼容性，但量产方案建议固定波特率以保证确定性。

## 五、收发操作时序

UART 的数据收发有轮询、中断、DMA 三种实现路径，选择直接决定了最高可用波特率与丢字节概率；此外 RS-485 半双工方向切换也有一组容易踩坑的时序。

**发送流程**：软件写入发送数据寄存器后，硬件移位寄存器逐位移出：先拉低一位作为起始位，再依次移出数据位（低位先发），接着是校验位（若使能），最后是停止位。一帧发送完成会置 TXE（发送数据寄存器空）标志；整个移位过程结束才置 TC（发送完成）标志。二者不可混淆：判断能否写入下一个字节用 TXE，判断 RS-485 能否切回接收必须用 TC。

**接收轮询方式**：软件循环查询接收标志并读取数据寄存器。实现最简单，但占用 CPU，且主循环被阻塞时极易丢字节，仅适用于极低波特率或纯调试场景。

**接收中断方式**：每个字节到达触发中断并送入软件环形缓冲区。相比轮询大幅降低丢包率，但在高波特率（如 921600bps 及以上）且中断频繁被其他高优先级抢占时仍有溢出风险，缓冲区深度应预留足够。

**接收 DMA 方式**：DMA 在数据寄存器与内存之间自动搬运，CPU 仅在半满、全满或空闲线中断时介入。这是高速率、大数据量场景的推荐方式，配合空闲线中断可实现不定长帧的自动接收，也是目前的主流做法。

**RS-485 半双工方向切换时序**：这是把 UART 扩展为 RS-485 时最关键的时序点，实现不当会直接导致帧头或帧尾丢失：

1. 发送前先将 DE/RE 拉高进入发送态，并等待收发器建立时间（通常数百纳秒到数微秒）。
2. 启动发送后，必须等到 TC 标志置位再拉低 DE/RE 切回接收态。仅判断 TXE 会导致最后一个字节尚未移位完成就被切断。
3. 切回接收后应等待总线线路恢复稳定再允许接收，避免把自身发出的数据回读进来。
4. 软件上应关闭回显，或能明确识别出自身发送的数据。

**空闲线与 Break**：空闲线检测用于判定一帧数据的结束，Break 信号（持续低电平）在某些协议中被用作帧起始或复位同步。两者均为可选能力，使用前需确认 MCU 与收发器是否支持。

## 六、硬件设计要点

结合 UART 异步、点对点、可远距离的特点，硬件设计中应重点落实以下各项：

- **交叉连接与共地**：TX 必须接对端 RX，且两个设备必须共地。没有共地，异步串口就没有电平参考，必然出错。
- **禁止 TTL 多机并联**：多个 TTL 输出直连会互相冲突。需要多机时使用 RS-485 或串口交换芯片。
- **严禁电平混接**：RS-232 的 ±15V 绝不可直接接入 MCU 的 IO；不同 TTL 电平域之间必须使用电平转换器件。
- **RS-485 终端与偏置**：总线两端各放置一个 120Ω 终端电阻（仅两端，中间节点不得放置）；配置 A 上拉、B 下拉的偏置电阻（典型 1kΩ 级）保证总线空闲时为确定电平；优先选用带失效保护（failsafe）的收发器。
- **RS-485 拓扑与节点数**：采用单段手拉手菊花链，避免星型分支。标准 32 单位负载，采用 1/8 单位负载收发器可扩展到 256 节点，选型时按实际节点数核算。
- **隔离设计**：工业场合应使用隔离收发器或光耦加隔离电源的方案。隔离两侧地不可跨接安规电容或直连，否则共模隔离失效。
- **防护器件**：对外引出的串口须配置 TVS 管（RS-485 建议使用专用总线防护器件），高要求场合再加共模电感与气体放电管；注意保护器件的结电容不得影响通信速率。
- **波特率误差核算**：设计阶段列出时钟源、分频系数与实际波特率误差表，确认总偏差在 ±1.5% 以内；高速率必须使用外部晶振。
- **流控预留**：即使当前不使用，也建议将 RTS/CTS 引出至测试点或 0Ω 位置。
- **调试串口**：预留标准 4Pin 或 5Pin 调试座（VCC/TX/RX/GND），并在丝印上标注波特率与引脚顺序，方便现场对接。
- **PCB 布局**：TTL 走线平行布线即可，保持地平面连续、远离电源与时钟源；RS-485 的 A/B 应按差分对紧耦合走线并控制长度偏差，差分阻抗约 120Ω，切忌把 A/B 分开绕远。
- **上电时序与 IO 容差**：互连的两个设备分属不同电源域且上电有先后时，先上电一侧的 TX 会向后上电一侧灌电流，可能造成闩锁或漏电。应选用 5V 容忍引脚，或加限流电阻与钳位二极管，并明确上电顺序要求。

## 七、典型应用场景

UART 应用面极广，从最简单的日志打印到工业现场总线都能覆盖，各类场景的设计关注点差异如下：

| 应用对象 | 典型用途 | 设计关注点 |
| --- | --- | --- |
| 调试控制台 | 固件日志输出、命令行交互 | 预留调试座、标注波特率、统一 TX/RX/GND 引脚顺序 |
| 无线模组 | 4G、GNSS、Wi-Fi、蓝牙的 AT 指令通道 | 模组默认波特率核对、大数据量时的流控、模组启动时序 |
| 工业总线 | RS-485 承载 Modbus RTU | 终端电阻与偏置电阻、单段菊花链、DE/RE 切换时序、隔离与防护 |
| PC 上位机 | USB 转串口（CDC） | USB 转串芯片选型、驱动兼容性、波特率自适应 |
| 定位授时 | GNSS NMEA 报文 | 默认 9600 波特率、报文以换行符分帧、1PPS 与串口的配合 |
| 多机通信 | 板间点对点命令通道 | 主从协议设计、应用层 CRC 与超时重传机制 |
| 老旧设备对接 | RS-232 仪表、医疗与工控设备 | DB9 引脚定义核对、负逻辑与电平确认、是否需要隔离 |

## 八、可靠性与测试验证

UART 是最容易"看起来能通、实际留隐患"的接口：常温下低速能通信，不代表高低温长期稳定，更不代表波特率裕量充足。应在设计阶段建立误差预算，并在验证阶段把关键指标量化。

**常见故障模式**：

| 故障现象 | 可能原因 | 排查建议 |
| --- | --- | --- |
| 完全无数据 | TX/RX 未交叉、未共地、电平不匹配 | 确认交叉接线；测量 GND 连通性；确认两侧电平标准一致 |
| 有数据但全是乱码 | 波特率不一致、帧格式（数据位/校验/停止位）不同 | 核对双方配置；用逻辑分析仪实测位宽反推波特率 |
| 能收不能发（或反之） | 单边走线断、引脚复用未配置、串口外设未使能 | 检查引脚复用配置；用示波器打 TX 是否有波形 |
| 首字节丢失 | RS-485 方向切换过早、上电后未等待串口稳定即发第一帧 | 改为等待 TC 标志再切换；上电延时后再发首帧 |
| 帧尾少字节 | RS-485 的 DE/RE 拉低过早（误用 TXE 而非 TC） | 改用 TC 标志判断发送完成 |
| 偶发丢字节 | 无流控导致缓冲溢出、中断被抢占、未使用 DMA | 启用硬件流控；改用 DMA 加空闲中断；增大缓冲区 |
| 高温或低压下乱码 | 内部 RC 时钟随温度电压漂移 | 改用外部晶振；重新核算波特率误差 |
| RS-485 点对点通、组网失败 | 终端电阻缺失或重复、A/B 接反、偏置缺失、节点超规 | 核对两端各一个 120Ω；统一 A/B 极性；加偏置电阻；核算节点数 |
| 长距离误码率高 | 波特率过高、未用屏蔽双绞线、分支过长 | 降速对比验证；换屏蔽双绞；改菊花链并缩短分支 |
| 接 RS-232 后烧 MCU | RS-232 电平直接接入 IO 引脚 | 必须加 MAX3232 类电平转换芯片 |
| 串口时通时断 | 接触不良、TVS 结电容过大、线上共模干扰 | 检查连接器；核对防护器件选型；增加共模电感 |

**测试要点**：

- 波形位宽实测：用示波器或逻辑分析仪测量单个位的时间宽度，反推实际波特率并与标称值比对。
- 帧格式解码：用协议解码功能整帧解码，确认数据位、校验位、停止位与预期一致，且为低位先行。
- 波特率误差核算：把时钟源精度、分频舍入误差、双方偏差累加，确认总偏差在允许范围内并留有余量。
- 长时间压力测试：连续大数据量收发并做逐字节或 CRC 校验，统计误码率与丢字节数，建议累计不少于数十万字节。
- 极限条件验证：在高低温与极限工作电压下重复压力测试，观察帧错误与溢出计数是否增长。
- RS-485 专项：测量 A/B 差分幅值与共模电压范围；验证多节点组网下的收发、终端电阻配置与总线空闲电平。
- 上电与插拔：验证上电过程中不产生误码帧、反复插拔不损坏接口；对外引出线完成 ESD 与浪涌测试。
- 错误计数使能：确认帧错误、奇偶错误、溢出错误的计数已开放并被软件记录。

## 九、设计检查清单

1. TX/RX 已交叉连接，两个设备之间可靠共地。
2. 两侧电平标准一致，不同电平域已加专用转换器件。
3. RS-232/RS-485 信号未直接接入 MCU 的 IO 引脚。
4. 波特率、数据位、校验位、停止位四项配置两侧完全一致。
5. 已完成波特率误差核算，总偏差小于 ±1.5%；高速率已使用外部晶振。
6. 未将多个 TTL 输出并联在同一根 RX 线上。
7. RS-485 总线两端各一个 120Ω 终端电阻，并已配置偏置电阻。
8. RS-485 采用单段手拉手拓扑，无星型长分支。
9. RS-485 方向切换使用 TC 标志而非 TXE，首帧丢失问题已实测验证。
10. 已根据数据量与速率确定是否需要 RTS/CTS 硬件流控，并已在原理图上预留。
11. 接收采用 DMA 或足够深度的环形缓冲，已使能帧错误、奇偶错误、溢出错误计数。
12. 应用层已定义明确的成帧规则（帧头、长度、CRC）与超时丢弃策略。
13. 对外引出的串口已配置 TVS 等防护器件，选型已核对结电容。
14. 工业场合已采用隔离方案，且隔离两侧地未短接。
15. RS-485 走线按差分对紧耦合布线，差分阻抗约 120Ω，走线未跨分割。
16. 不同电源域互连时的上电时序、IO 容差与灌电流风险已评估并处理。
17. 已完成调试串口的座型、引脚顺序与波特率丝印标注。
18. 已完成高低温与极限电压下的长时间压力测试并统计误码率。

> 注：本文为 UART 接口的通用设计说明。UART 只定义逻辑协议而无电气标准，具体项目的波特率上限、时序参数与收发器特性最终以所用 MCU 与收发器芯片的数据手册为准，关键参数应在样板阶段通过实测确定。
