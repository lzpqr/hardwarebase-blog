## 一、文档目的与适用范围

本文档规定硬件产品中调试与测试访问接口（JTAG 与 SWD）的信号定义、电气要求、连接器规范、协议与访问模型、操作流程、PCB 布局、安全管控与测试验证要求，作为原理图设计、PCB 设计、调试工具选型与量产工艺文件编制的通用依据。

适用范围：MCU、SoC、FPGA、CPLD 等器件的在线调试与程序下载、边界扫描测试、量产烧录接口，以及跟踪输出通道。芯片内部扫描链的实现细节、调试器软件的实现方式不在本文档范围内；具体器件的调试端口使能方式、读保护等级与熔断操作，以对应芯片的数据手册与参考手册为准。

## 二、接口概述

JTAG 与 SWD 是两条通向同一个调试访问端口（DAP，Debug Access Port）的路径，前者是通用行业标准，后者是 ARM 为减少引脚而提出的替代方案。二者的定位与特征如下：

- **JTAG（IEEE 1149.1）**：起源于边界扫描测试标准，标准配置为四线（TCK、TMS、TDI、TDO）加可选的 nTRST。支持菊花链、边界扫描 ICT 测试、FPGA/CPLD 配置与在线逻辑分析，是通用性最强、产业链支持最完整的调试与测试接口。
- **SWD（Serial Wire Debug）**：ARM 提出的双线调试接口，只需 SWCLK 与 SWDIO 两根线即可完成与 JTAG 相当的调试功能，另有一根可选的 SWO 用于跟踪输出。引脚占用少、抗干扰能力好，是当前 Cortex-M 系列器件的主流选择。
- **共用同一 DAP**：两种接口访问的是同一套调试资源，可通过特定的位序列在线切换，因此硬件上只需引出 SWD 两线也能保留 JTAG 能力。
- **非功能性接口**：调试口不参与产品的正常工作，不传输业务数据，但决定三件事——研发阶段的调试效率、量产阶段的可测性与烧录效率、以及产品交付后的安全性。
- **安全属性突出**：这是本系列其他接口都不具备的特点。调试口能读写全部内存与寄存器，是产品最主要的攻击面之一，因此必须在设计阶段就规划好量产时的封锁或降级策略。
- **速率可协商**：接口本身不固定速率，由调试器与目标的电气条件共同决定，通常从低速起步再逐步提升，实际可用速率受线缆长度与 PCB 走线质量限制。

选择 JTAG 还是 SWD，本质上是在"通用性与测试能力"和"引脚占用与抗干扰"之间取舍：需要边界扫描或 FPGA 配置的场合必须用 JTAG；纯 MCU 产品优先用 SWD。

## 三、物理层设计

物理层要解决三件事：引哪些线、用什么连接器、以及在怎样的走线与端接条件下时钟边沿仍然可靠。

### （一）JTAG 信号定义

| 信号 | 方向 | 说明 |
| --- | --- | --- |
| TCK | 调试器 → 目标 | 测试时钟，所有状态转换与移位都以它的上升沿为基准 |
| TMS | 调试器 → 目标 | 测试模式选择，决定 TAP 状态机的走向，需可靠上拉 |
| TDI | 调试器 → 目标 | 串行数据输入，送入指令寄存器或数据寄存器 |
| TDO | 目标 → 调试器 | 串行数据输出，多器件链中前一级 TDO 接后一级 TDI |
| nTRST | 调试器 → 目标 | 可选，低电平有效的 TAP 异步复位，多数器件可省略 |
| nRESET | 调试器 → 目标 | 建议引出，低电平有效的系统复位，用于连接受控复位 |
| VREF / VTref | 目标 → 调试器 | 目标板 IO 电平参考，供调试器判断电平门限，必须连接 |
| GND | — | 至少 2 根，与调试器共地，是信号完整性的基础 |

### （二）SWD 信号定义

| 信号 | 方向 | 说明 |
| --- | --- | --- |
| SWCLK / SWDCLK | 调试器 → 目标 | 串行时钟，由调试器提供，目标板上应下拉 |
| SWDIO | 双向 | 串行数据，半双工，靠转向周期切换方向，目标板上应上拉 |
| SWO / SWV | 目标 → 调试器 | 可选，串行跟踪输出，承载 ITM 与数据观察点信息 |
| nRESET | 调试器 → 目标 | 建议引出，支持复位状态下连接与自动复位运行 |
| VREF / VTref | 目标 → 调试器 | 目标板 IO 电平参考，供调试器判断电平门限 |
| GND | — | 至少 2 根，与调试器共地 |

### （三）电气特性与速率

调试口采用 CMOS 电平，跟随目标器件的 IO 供电，常见为 3.3V、2.5V 或 1.8V。目标板须把 IO 参考电压通过 VREF 提供给调试器，调试器据此设置输入门限与输出电平，这是跨电平域可靠工作的前提。

可用速率由器件能力、线缆长度、PCB 走线质量三者取小值决定，常见的工程取值区间如下：

- **识别阶段**：通常以 100kHz~1MHz 起步，确保线路复位与切换序列被可靠接收。
- **常规调试**：板载短走线、1.8V~3.3V 条件下常用 4~10MHz。
- **高速下载**：走线极短且端接良好时可到 20~40MHz，但需实测验证。
- **长线缆或转接**：排线超过 15cm 时通常需降到 1~2MHz 才能稳定。

需要注意：调试口的速率瓶颈往往不在芯片，而在排线与接插件带来的反射与串扰。设计时不要盲目追求标称最高速率，而要保证在量产夹具与长线缆条件下仍有足够裕量。

### （四）连接器与引脚排列

连接器选型应在项目立项阶段确定并在全公司内统一，避免不同项目调试线互不通用。常见形式如下：

| 连接器 | 间距 | 引脚数 | 特点与适用 |
| --- | --- | --- | --- |
| ARM 20-pin JTAG | 2.54mm | 20 | 最早的通用标准，含完整 JTAG 与一路地，体积大，适合开发板 |
| Cortex 10-pin | 1.27mm | 10 | 当前主流，同时支持 JTAG 与 SWD，体积小，适合量产小板 |
| Cortex 20-pin | 1.27mm | 20 | 在 10-pin 基础上增加更多接地与跟踪信号，适合带 SWO 的场合 |
| 10-pin 大间距 | 2.54mm | 10 | 便于手工焊接与飞线，用于样机阶段 |
| 4-pin SWD | 1.25mm / 2.54mm | 4 | 仅 VREF、SWDIO、SWCLK、GND，用于极致小型化产品或测试点 |
| 无连接器测试点 | 焊盘 / 过孔 | 按需 | 靠针床或弹片微针接触，用于量产烧录，需保证定位精度 |

无论采用哪种形式，连接器都必须具备防反插结构（定位缺口、不对称引脚排列或定位柱），并在丝印上标注 1 脚方向与信号名。反接轻则连不上，重则通过 VREF 与电源引脚倒灌烧毁器件。

### （五）拓扑结构

- **JTAG 菊花链**：所有器件的 TCK、TMS 并联，前一级 TDO 接后一级 TDI，形成一条扫描链。这是 JTAG 支持多器件的根本方式，链上器件数量可从 IDCODE 扫描结果得到。
- **SWD 点对点**：标准 SWD 面向单器件，多个器件不能像 JTAG 那样串成链，只能各自引出独立的 SWD 口，或增加外部多路切换。
- **多器件选择**：较新的调试架构支持多器件接入同一组 SWD 信号，但需要目标选择序列与器件标识参与寻址，硬件设计前应确认所用芯片与调试器是否同时支持。
- **禁止并联数据线**：不同器件的 TDO/SWDIO 不得直接并联，会造成驱动冲突与电平不定。

### （六）上拉下拉与端接

- **SWDIO 上拉**：目标板上应在 SWDIO 加约 100kΩ 上拉，保证线缆断开时数据线不浮空。
- **SWCLK 下拉**：目标板上应在 SWCLK 加约 100kΩ 下拉，避免上电期间误触发时钟。
- **TMS 与 TDI 上拉**：JTAG 口建议上拉，使断开调试器时 TAP 状态机稳定在复位态，防止误入测试模式。
- **串联阻尼电阻**：驱动侧串联 22~100Ω 抑制反射，取值需结合走线长度与速率实测调整。
- **禁止并联电容**：时钟与数据线上不得加滤波电容，这会劣化边沿、限制最高速率，是调试口常见的人为故障源。

## 四、协议层设计

调试口与数据接口不同：它没有"用户数据帧"，而是由调试器发起的一系列寄存器访问事务。理解这一点，协议层就只剩下两组内容——JTAG 的状态机与寄存器模型，以及 SWD 的请求应答帧结构。

### （一）JTAG TAP 状态机

TAP 控制器是一个由 TMS 在 TCK 上升沿驱动的十六状态有限状态机，所有操作都通过导航到相应状态完成。关键状态包括：

- **Test-Logic-Reset**：复位态，TMS 保持高电平连续 5 个 TCK 即可无条件到达，是恢复通信的标准手段。
- **Run-Test-Idle**：空闲态，指令执行阶段停留在此。
- **Select-DR-Scan 与 Select-IR-Scan**：分别进入数据寄存器通路与指令寄存器通路。
- **Capture、Shift、Exit1、Pause、Exit2、Update**：捕获、移位、暂停与更新四段流程，DR 与 IR 各有对应的一组。

典型的操作序列是：导航到 Shift-IR 移入指令 → 经 Update-IR 生效 → 导航到 Shift-DR 移入或移出数据 → 经 Update-DR 完成操作。因此 JTAG 的一切行为都可以归结为"选指令、搬数据"两步。

### （二）JTAG 寄存器与常用指令

| 指令 | 作用 | 说明 |
| --- | --- | --- |
| BYPASS | 旁路 | 把器件在扫描链中缩成 1 位寄存器，用于屏蔽不需要操作的器件 |
| IDCODE | 读器件标识 | 返回厂商号、部件号与版本，是识别器件与链上器件数量的依据 |
| EXTEST | 外部测试 | 把边界扫描单元的值驱动到引脚，用于 ICT 的开短路与互连测试 |
| SAMPLE / PRELOAD | 采样与预置 | 采样引脚状态或预置扫描单元，为后续测试做准备 |
| INTEST | 内部测试 | 对芯片内部逻辑施加测试向量，较少使用 |
| USERCODE | 读用户码 | 返回用户可编程标识，常用于可编程器件区分配置版本 |

边界扫描测试依赖 BSDL 文件描述每个器件的引脚与扫描单元结构。项目上做 ICT 之前，必须先收集齐链上所有器件的 BSDL 文件，否则无法生成测试向量。

### （三）SWD 帧结构

SWD 的每一次访问由主机发起的三段构成：请求包、应答、数据段。其中 SWDIO 是半双工的，每次方向切换都要插入若干转向周期。

请求包共 8 位，从低位到高位依次为：

```text
Start(1) · APnDP(1) · RnW(1) · A[2:3](2) · Parity(1) · Stop(0) · Park(1)
```

- **Start**：固定为 1，标志一帧开始。
- **APnDP**：0 表示访问调试端口寄存器，1 表示访问访问端口寄存器。
- **RnW**：1 表示读，0 表示写。
- **A[2:3]**：两位地址，在四个寄存器组中选择。
- **Parity**：前面各位的奇偶校验，使整包中 1 的个数为奇数。
- **Stop 与 Park**：结束位，Park 期间主机释放数据线，为从机应答让出总线。

应答为 3 位，含义如下：

| ACK 值 | 含义 | 主机应采取的动作 |
| --- | --- | --- |
| 001 OK | 操作成功 | 继续后续数据段 |
| 010 WAIT | 目标忙，请求重试 | 重试同一请求；连续重试过多时应降速或中止 |
| 100 FAULT | 访问出错，需清除 | 读取控制状态寄存器并清除错误标志后再重试 |
| 111 无响应 | 目标未应答 | 检查接线、供电、复位与端口使能，重新发起线路复位 |

数据段为 32 位数据加 1 位奇偶校验。写操作的顺序是请求、应答、转向、数据；读操作的顺序是请求、应答、数据、转向。方向切换的转向周期通常为 1 个时钟，具体位数由调试器根据配置插入——它是 SWD 在同样时钟频率下效率低于 JTAG 的原因之一。

### （四）JTAG 与 SWD 的切换序列

两种接口通过一组特定的位序列在线切换，这是"两根线也能保留 JTAG 能力"的技术基础。切换流程为：

1. 线路复位：主机驱动 TMS/SWDIO 为高电平，送出至少 50 个时钟周期。
2. 送选择序列：送出 16 位选择序列（按位发送顺序为 0x79E7，按高位在先书写为 0xE79E），用于从 JTAG 切到 SWD；反向切换使用另一组序列。
3. 再次线路复位：再送出至少 50 个高电平时钟周期，使切换生效。
4. 读标识确认：读取器件标识寄存器，确认接口类型与器件存在。

这一序列全部由调试器软件完成，硬件设计者只需保证 TMS/SWDIO 与时钟线可靠连接、未被其他电路拉死即可。

### （五）调试端口寄存器模型

调试访问端口分为两层：调试端口（DP）负责链路与状态管理，访问端口（AP）负责把访问转换到具体的总线或资源上。常用寄存器如下：

| 寄存器 | 地址 | 说明 |
| --- | --- | --- |
| DPIDR | DP 0x00 | 调试端口标识，读取它可确认链路连通与接口类型 |
| CTRL/STAT | DP 0x04 | 控制与状态，含上电调试域请求、错误标志与溢出标志 |
| SELECT | DP 0x08 | 选择当前操作的 AP 与寄存器组 |
| RDBUFF | DP 0x0C | 读缓冲，取回上一次读操作的实际结果 |
| CSW | AP 0x00 | 访问端口控制状态，含传输大小与自动递增设置 |
| TAR | AP 0x04 | 传输地址寄存器，指定要访问的内存地址 |
| DRW | AP 0x0C | 数据读写寄存器，写它即发起一次访问 |
| IDR | AP 0xFC | 访问端口标识，用于识别 AP 类型与能力 |

### （六）SWO 跟踪输出

SWO 是可选的单向输出，用于把芯片内部的事件与数据在不中断运行的前提下送出，常见用途是打印调试信息、采样变量与统计执行时间。它的关键约束是：

- 输出编码方式（曼彻斯特编码或异步串行）与波特率必须由调试器与目标事先约定一致，否则解出来全是乱码。
- 波特率由跟踪时钟分频得到，需保证目标时钟配置与调试器设置匹配。
- 不使用时应把该引脚配置为普通功能或悬空处理，避免引入不必要的耦合。

### （七）JTAG 与 SWD 对比

| 对比项 | JTAG | SWD |
| --- | --- | --- |
| 最少信号数 | 4（TCK、TMS、TDI、TDO） | 2（SWCLK、SWDIO） |
| 数据方向 | TDI 与 TDO 分开，全双工 | 半双工，需转向周期 |
| 多器件支持 | 原生菊花链，标准成熟 | 原生不支持，需额外机制或独立引出 |
| 边界扫描 ICT | 支持，是标准用途 | 不支持 |
| FPGA/CPLD 配置 | 支持 | 不支持（多数厂商不支持） |
| 跟踪输出 | 需并行跟踪口 | 可用单根 SWO |
| 调试能力 | 完整 | 与 JTAG 基本相当 |
| 典型选择 | 需测试与配置能力的复杂板卡 | 纯 MCU 产品、引脚紧张的小板 |

## 五、调试访问操作流程

操作流程由调试器软件与调试代理完成，硬件设计者了解它的意义在于：当连接失败时，能判断问题出在链路、供电、复位还是器件被封锁。

**建立连接与识别器件**：

1. 调试器检测 VREF，确认目标板已上电并确定 IO 电平。
2. 送出线路复位序列，把接口置于确定状态。
3. 按需送出接口切换序列，确定使用 JTAG 还是 SWD。
4. 读取器件标识寄存器（JTAG 读 IDCODE，SWD 读 DPIDR）。
5. 通过控制状态寄存器请求上电调试域与系统调试域。
6. 枚举访问端口，确认内存访问通路可用。

只要第 4 步读不到正确的标识值，其后的一切操作都无从谈起，因此"读 IDCODE/DPIDR"是判断硬件连接是否正确的第一判据。

**访问内核与内存**：典型的内存访问序列是：写 SELECT 选择目标 AP 与寄存器组 → 写 TAR 指定地址 → 写或读 DRW 发起访问 → 读 RDBUFF 取回上一次读的结果。需要注意两点：读操作的结果有延迟，必须再读一次缓冲寄存器才能拿到数据；访问可能返回 WAIT，需要重试机制。

**Flash 编程流程**：

1. 解锁 Flash 控制器（不同厂商的解锁序列不同）。
2. 擦除目标扇区或整片。
3. 按页写入数据并等待完成标志。
4. 回读校验，比对写入内容的正确性。
5. 按需设置读保护与写保护，复位运行。

为提升速度，调试器通常把一段 Flash 编程算法下载到目标芯片的 SRAM 中执行，由算法在内部分块搬运数据。因此烧录速度不仅取决于接口速率，还取决于 SRAM 容量与目标芯片的编程时间。

**跟踪数据采集**：使用 SWO 时，需要先配置芯片内部的跟踪单元与引脚输出，设置编码方式与波特率，再让调试器按相同参数解码。若两侧参数不一致，表现为完全无输出或全是乱码，这一故障在调试中非常常见且容易被误判为硬件问题。

**多器件与边界扫描**：边界扫描测试时，先扫描整条链得到器件列表与各自的 IDCODE，确认器件型号、数量与方向是否与 BSDL 描述一致；然后把不参与测试的器件置为 BYPASS，对目标器件加载 EXTEST 指令并驱动引脚，完成开短路与互连测试。链上任何一个器件的 TDI-TDO 方向接反或焊接不良，都会导致整条链无法识别。

**连接失败时的恢复手段**：

- 降速重试：把时钟降到最低档再连，是排除信号完整性问题最有效的手段。
- 复位状态下连接：先拉住系统复位再发起连接，可在程序跑飞或误配置调试引脚时救回芯片。
- 检查供电与复位：确认内核、IO 与调试域电源均正常，复位信号未被拉死。
- 解除读保护：已设置读保护的器件需整片擦除才能恢复调试访问，操作前必须确认允许丢失数据。
- 检查引脚复用：确认软件未把调试引脚配置为普通功能，也未关闭调试时钟。

## 六、硬件设计要点

调试口的硬件设计有三条主线：连接可靠、不影响产品功能、交付后可控。

- **连接器必须防反插**：采用带定位缺口的连接器或非对称引脚排列，并在丝印上标明 1 脚方向与信号名称，杜绝反接烧毁。
- **VREF 必须连接**：由目标板把 IO 参考电压送到调试器，这是跨电平域工作的前提，不可省略或用固定电阻代替。
- **地线数量充足**：连接器上至少安排 2 根地线，最好让每根信号线旁边都有地，形成回流路径。
- **确认引脚复用冲突**：调试引脚在多数芯片上默认是调试功能，但也可被配置为普通输入输出。原理图上应明确标注其用途，软件不得在初始化时误改。
- **走线尽量短且同组**：时钟与数据线应同组平行走线，总长度尽量短，避免绕远与打过孔过多。
- **不跨分割**：调试信号不得跨地平面分割走线，否则回流路径中断会造成误码，表现为间歇性连接失败。
- **串联阻尼电阻**：驱动侧串联 22~100Ω，靠近目标器件放置，抑制反射。
- **正确配置上下拉**：SWDIO 上拉、SWCLK 下拉约 100kΩ，JTAG 的 TMS 与 TDI 上拉，保证断开调试器时状态确定。
- **禁止并联滤波电容**：时钟与数据线上不得加电容，这是限制速率与导致连接失败的最常见人为错误。
- **SWO 预留**：需要跟踪功能的产品应把 SWO 引脚引出；暂不使用时应留测试点，便于后期排查。
- **复位信号引出**：把系统复位引到连接器，可支持自动复位运行与复位状态下连接，大幅提升调试与量产效率。
- **量产安全管控**：产品交付前应通过读保护、熔断位或禁用调试口等方式关闭调试访问，并预留受控的恢复通道（如特定的引导升级接口），在安全性与售后可维护性之间取得平衡。

## 七、典型应用场景

调试口在不同阶段承担的角色差别很大，设计重心也随之不同：

| 应用场景 | 接口形式 | 设计关注点 |
| --- | --- | --- |
| MCU 在线调试 | SWD 两线 | 引脚复用确认、上下拉配置、连接器防反、复位引出 |
| FPGA / CPLD 配置 | JTAG 四线 | 菊花链顺序、TCK 速率上限、配置器件与配置模式配合 |
| 边界扫描 ICT | JTAG 链 | BSDL 文件齐备、TDI-TDO 方向正确、链上器件全部可扫描 |
| 量产烧录 | SWD 或 JTAG | 针床或弹片接触可靠性、烧录节拍、失败重试与数据统计 |
| 多核 SoC 调试 | JTAG 加跟踪口 | 多核连接拓扑、跟踪带宽、供电与复位时序 |
| 安全产品 | SWD（受控） | 读保护等级、熔断策略、售后恢复通道与密钥管理 |
| 逻辑在线升级 | JTAG | 升级期间不掉电、失败可回退、状态指示 |

## 八、可靠性与测试验证

调试口虽然不参与产品功能，但它一旦失效，研发停滞、量产停线、售后无法定位，代价很高。因此验证重点在"连接成功率"与"量产一致性"两项。

**常见故障模式**：

| 故障现象 | 可能原因 | 排查建议 |
| --- | --- | --- |
| 读不到器件标识，返回全 0 | 未上电、VREF 未接、接地不良、复位被拉住 | 测量目标板各路电源与 VREF；确认复位电平；检查连接器引脚顺序 |
| 读不到器件标识，返回全 1 | 数据线断开或浮空、连接器接触不良、线缆断线 | 用万用表通断档逐根查线；确认 SWDIO/TDO 上拉是否存在 |
| 连接不稳定，需降速才能连 | 走线过长、跨分割、串阻缺失、排线质量差 | 缩短走线与线缆；补串阻；检查地平面连续性 |
| 只能连一次，之后连不上 | 程序把调试引脚改成了普通功能、关闭了调试时钟 | 检查初始化代码对调试引脚与调试时钟门控的配置；用复位状态下连接救回 |
| 能识别但下载失败 | Flash 未解锁、写保护、供电不足、算法与器件不匹配 | 核对器件型号与 Flash 算法；检查编程时供电是否满足要求 |
| 烧录速度远低于预期 | 速率被限制、算法在 SRAM 中运行受限、等待周期过多 | 提高接口速率；核对时钟配置；统计擦写时间占比 |
| SWO 无输出 | 编码方式或波特率与调试器不一致、跟踪时钟未配置 | 核对芯片端跟踪配置与调试器设置；先确认引脚有波形再谈解码 |
| JTAG 链上器件数量不对 | 链上器件方向接反、焊接不良、BSDL 与实际型号不符 | 逐个器件扫描 IDCODE；核对 BSDL 文件版本 |
| 边界扫描报大量短路 | 未正确 BYPASS 无关器件、引脚电平冲突 | 确认链上无关器件已置旁路；检查被测网络的外部上拉下拉 |
| 烧录后无法再次连接 | 已设置读保护或熔断位、程序进入低功耗关闭调试域 | 确认读保护策略；整片擦除恢复；检查低功耗模式配置 |
| 调试口时好时坏 | 连接器磨损、针床接触不良、虚焊 | 更换连接器或探针；检查焊点；在量产夹具上做接触可靠性验证 |

**测试要点**：

- 连通性：在开发板、样机、量产夹具三种条件下分别验证能否稳定读到器件标识。
- 速率裕量：从最低速逐级提升，记录稳定工作的最高时钟频率，确认量产使用的速率留有足够裕量。
- 波形质量：用示波器观测时钟与数据波形，确认边沿单调、无明显振铃与过冲。
- 上下电重复：反复上电掉电并重复连接，确认每次都能识别，无需要重新插拔的情况。
- 长线缆与转接：在量产使用的线缆长度与转接板条件下复测，确认速率与稳定性满足产线节拍要求。
- 烧录一致性：连续烧录足够数量的样机，统计首次成功率与平均节拍，确认无偶发失败。
- 校验正确性：烧录后回读比对，确认写入内容与源文件完全一致。
- 安全策略验证：确认读保护、写保护与调试口禁用操作生效，并验证预留的恢复通道可用。
- ESD 与浪涌：对引出的调试连接器做接触放电测试，确认不会损坏器件；必要时增加防护器件。
- 极限条件：在高低温与极限电压下重复关键连接测试，确认调试访问在全温范围内稳定。

## 九、设计检查清单

1. 已确定使用 JTAG 还是 SWD，或两者兼容引出，并在原理图上明确标注。
2. 连接器已选型且具备防反插结构，丝印已标明 1 脚方向与信号名称。
3. VREF 已由目标板引出，GND 不少于 2 根。
4. 已核对调试引脚与器件默认功能，确认软件初始化不会误配置为普通功能。
5. SWDIO 已上拉、SWCLK 已下拉（约 100kΩ）；JTAG 的 TMS 与 TDI 已上拉。
6. 驱动侧已串联 22~100Ω 阻尼电阻，时钟与数据线上未并联滤波电容。
7. 调试信号走线短、同组平行，未跨地平面分割。
8. 系统复位信号已引至连接器，支持复位状态下连接。
9. 需要跟踪功能的产品已引出 SWO，并在文档中记录编码方式与波特率约定。
10. 采用 JTAG 链时，链上器件顺序、TDI-TDO 方向与 BSDL 文件齐备性已确认。
11. 已实测记录稳定工作的最高时钟频率，量产使用的速率留有裕量。
12. 已在开发板、样机、量产夹具三种条件下验证连接成功率。
13. 已在量产线缆长度与转接条件下复测速率与稳定性。
14. 已连续烧录足够数量样机，统计首次成功率与平均节拍。
15. 烧录后回读校验通过，内容比对一致。
16. 量产的安全策略（读保护等级、熔断位、调试口禁用）已确定并在工艺文件中写明。
17. 售后恢复通道已设计并验证可用，恢复流程不影响安全目标。
18. 调试连接器已完成 ESD 测试，防护措施到位。

> 注：本文为 JTAG 与 SWD 调试接口的通用设计说明。具体器件的调试端口使能方式、读保护等级、熔断操作与时序参数，最终以所用芯片的数据手册与参考手册为准；量产烧录策略应在样板阶段与工艺部门共同确定并实测验证。
